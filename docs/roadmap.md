# Roadmap

## 개요
지역생활 정보 플랫폼 MVP 개발 단계와 완료 시나리오를 정의합니다.

**목표**: 개발 환경 설정

**작업**:
- NestJS 프로젝트 설정
- PostgreSQL 설정
- Redis 설정
- Nuxt 프로젝트 설정
- PWA 설정
- Docker 개발환경 구성
- TypeORM 설정
- 기본 모듈 구조 생성

**완료 기준**:
- Backend 서버 실행 가능
- Frontend 서버 실행 가능
- DB 연결 성공
- Redis 연결 성공
- Docker Compose로 전체 스택 실행 가능

**예상 기간**: 1주

## MVP 완료 시나리오

다음 과정이 실제로 동작해야 MVP 완료로 간주합니다.

### 1. 사용자 접속
- 사용자가 웹사이트 접속
- 로그인 화면 표시

### 2. SNS 로그인
- 카카오/네이버/Google 중 하나로 로그인 선택
- SNS 로그인 페이지로 이동
- 사용자 승인
- 로그인 성공

### 3. 사용자 자동 생성
- 최초 로그인 시 사용자 자동 생성
- Access Token + Refresh Token 발급
- 자동 로그인 완료

### 4. 지역 설정
- 지역 설정 화면 표시
- 사용자가 지역 선택
- 지역 저장

### 5. 관심분야 설정
- 관심분야 설정 화면 표시
- 사용자가 관심분야 선택
- 관심분야 저장

### 6. 기관 확인
- 주변/관심 기관 목록 표시
- 기관 검색 가능
- 기관 상세 확인 가능

### 7. 기관 연결
- 관심 있는 기관 연결
- 연결된 기관 목록 표시

### 8. 데이터 수집
- 문화포털 Open API 데이터 수집
- 데이터 정규화
- DB에 콘텐츠 저장

### 9. 콘텐츠 목록 확인
- 콘텐츠 목록 조회
- 다양한 검색 조건으로 필터링
- 콘텐츠 표시

### 10. 추천 확인
- "이런 거 어때요?" 추천 표시
- 사용자 정보 기반 추천
- 추천 콘텐츠 클릭

### 11. 상세 확인
- 행사 상세 페이지 이동
- 상세 정보 확인
- 원문/신청 페이지로 이동

### 12. Web Push 권한
- Web Push 권한 요청
- 사용자 승인
- 구독 완료

### 13. 알림 수신
- 새로운 추천 알림 수신
- 신규 콘텐츠 알림 수신
- 마감 임박 알림 수신

### 14. 가족 연결
- 자녀가 부모님 연결 요청
- 부모님 본인 SNS 로그인
- 연결 수락
- 권한 부여

### 15. 부모님 설정
- 자녀가 부모님 기관 연결
- 자녀가 부모님 관심분야 설정
- 부모님에게 알림 발송

## 개발 원칙

### 1. 문서 우선
코드를 작성하기 전에 프로젝트 구조와 데이터 모델을 먼저 설계합니다.

### 2. MVP 범위 준수
기존 요구사항에 없는 기능을 임의로 추가하지 않습니다.

### 3. 테스트 코드
모든 주요 기능에는 테스트 코드를 작성합니다.

### 4. 환경변수 사용
API Key와 Secret을 코드에 넣지 않고 환경변수를 사용합니다.

### 5. DB Migration
DB Migration을 사용하여 스키마를 버전 관리합니다.

### 6. 에러 대응
외부 API 장애 및 데이터 중복/변경 상황을 고려합니다.

## 리스크 관리

### 기술적 리스크
- **외부 API 장애**: 기존 데이터로 서비스 동작, 재시도 로직
- **Redis 장애**: PostgreSQL 기반 서비스 동작
- **데이터 중복**: Unique 제약조건, Upsert 로직

### 일정 리스크
- **Phase 일정 지연**: 병렬 작업 최대화, MVP 범위 엄수
- **요구사항 변경**: 변경 영향 분석, 일정 재조정

### 보안 리스크
- **개인정보 유출**: 암호화, 접근 제어, 감사 로그
- **API 보안**: HTTPS, JWT, Rate Limiting
